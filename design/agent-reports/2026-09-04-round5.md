### M-1 (Minor) — three ambient-git channels still reach the fixture; all fail LOUD, none fail silent

`52a5bb51` neutralises the developer's global `core.excludesFile` repo-locally, and that
holds — including at **SYSTEM** level, which the brief asked about (A-2 probe 4: PASS).
Three channels route around it, all measured red on the shipped test:

| channel | mechanism | result |
|---|---|---|
| `GIT_TEMPLATE_DIR=<dir>` with `info/exclude` | `git init` copies the template's `info/exclude` into `$GIT_DIR`, which outranks `core.excludesFile` | **FAIL** |
| global `init.templateDir` (i.e. a hostile `HOME`) | same, via config rather than env | **FAIL** |
| `GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_0=core.excludesFile` | command-level config outranks repo-local config | **FAIL** |

All three produce the identical panic — *"got 2 note / 0 committed"* — i.e. the axis
assertion catches every one of them. **The failure mode is a false FAIL on an exotic
machine, never a false PASS**, so this is hardening, not a defect.

The consequence for the record: `52a5bb51`'s subject line, *"hermetic against the
developer's global git config"*, is exact for `core.excludesFile` and **overstated as a
general claim** — a global `init.templateDir` is global git config and still reds the test.
The doc comment in the code is narrower and more accurate ("global ignore rules").

Optional one-line close, if wanted: add `.env_remove("GIT_TEMPLATE_DIR")` plus
`GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_0..n` / `GIT_CONFIG_VALUE_0..n` to the fixture's `git`
closure, or pass `git init --template=<empty dir>`. **Not required for merge.**

### A-3 The Windows surface, closed by proxy

The riskiest thing here runs on `windows-latest` — `.github/workflows/ci.yml` line 23 is a
three-OS matrix and line 35 is `cargo test --workspace --locked`, so yes, this test runs
there. Four sub-risks, each measured rather than reasoned:

- **Backslashes in the pathspec.** Would break the `design/forms/**/*.pdf` match and label
  the pdf `Committed`. **Closed at the source**: `collect_sources` ends with
  `out.push(rel.to_string_lossy().replace('\\', "/"))`, so `rel` is always forward-slash.
- **Backslashes in the config VALUE** (`root.join(...).to_str()` on Windows). Measured with
  a literal Windows path: git writes `excludesFile = C:\\Users\\…` and reads back
  `C:\Users\runneradmin\AppData\Local\Temp\.tmpXYZ\no-such-global-excludes` — byte-identical
  round trip. No "bad config line", so no exit-128 cascade.
- **A `core.excludesFile` that does not exist.** Measured: git ignores it silently — no
  warning, no non-zero exit. `check-ignore` still answered 0 for the pdf and 1 for the html.
- **Odd characters from `TMPDIR`** (spaces, `#`, `;`): probe 8, PASS.

### A-4 The one that decides convergence: can this test pass while the axis is collapsed?

A false PASS needs `1 note / 1 committed` while `git check-ignore` is *not* actually reading
the fixture's own `.gitignore`. The pdf must therefore be reported **not ignored** by some
ambient source. Per gitignore precedence, a repo `.gitignore` outranks `$GIT_DIR/info/exclude`
which outranks `core.excludesFile`, so no ambient source can negate it. Verified both ways:

- probe 10, global excludes `!design/forms/**/*.pdf` + `!*.pdf` → PASS (unchanged);
- probe 16, template `info/exclude` with the same negations → PASS (unchanged);
- raw corroboration: `.gitignore` = `design/forms/**/*.pdf`, `.git/info/exclude` =
  `!design/forms/**/*.pdf` → `git check-ignore -q design/forms/2025/a.pdf` exits **0**,
  still ignored.

**Therefore `1 note / 1 committed` is reachable only when check-ignore genuinely works
against the fixture's own ignore file.** The assertion cannot be satisfied vacuously. That
is the property the last four rounds were circling, and it now holds by construction.

### A-5 Cross-test interference under `cargo test` (which is what CI runs, not nextest)

CI runs `cargo test --workspace`, so xtask's 67 tests share **one process and its
environment** — unlike local `make check`, where nextest gives each test its own process. So
a sibling test mutating process env could reach the git fixture. One does:
`examples.rs:2315` calls `std::env::set_var("HOME", &junk_home)`.

Not a hazard, for two independent reasons: it mutates only `HOME`,
`BTCTAX_PRICE_CACHE`, `BTCTAX_NOW`, restoring them via an `EnvRestore` guard that runs on
panic too; and a junk `HOME` makes git *more* hermetic, not less — measured as probe 13,
PASS. No xtask test calls `set_current_dir`, and the git fixture mutates only child
environments (`.env_remove` on a `Command`), never the process. No interference.

### A-7 The real-repo blast radius of a mislabelled `Storage`, and why it is loud

`storage` is not cosmetic: `verify()` checks a `Committed` entry's file **and its hash**,
while for `Note` it checks only that the `.txt` exists. So a mislabel would weaken
`verify`. Measured on the committed manifest: 102 entries, 60 note / 42 committed, and
**zero committed entries have a sibling `.txt` note**. A `Committed → Note` flip therefore
produces `Problem::MissingNote` on the very next `every_manifest_entry_resolves_and_hashes_true`,
and a `Note → Committed` flip produces 60 `MissingFile`s in any normal (unfetched) tree.
Both directions red immediately. There is no silent path.

another repo's config or re-init it bare; a nested repo could not leak its ignore rules into
