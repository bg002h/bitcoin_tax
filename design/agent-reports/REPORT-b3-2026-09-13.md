## I-1 (Important, THIS RANGE) — `blockers::year_sites` is blind to the idiom `return_refuse.rs` now uses, and the report prints a universal claim over 134 variants anyway

`crates/xtask/src/blockers.rs:1137`, `pub fn year_sites(body: &str)`. Its entire scan is:

```rust
for needle in ["ri.tax_year", "NotUsable::"] {
```

A refusal site that reads the tax year through a **function parameter** matches neither needle. It is
therefore not counted — and it is **not reported as UNCLASSIFIED either**, because `unclassified` is
computed only over the sites those two needles already found (`blockers.rs:1272-1288`). A site the
needles miss cannot become an UNCLASSIFIED row.

**Measured, not argued.** Four `RefuseReason` variants carry a `year: i32` payload, i.e. cannot be
raised without reading the tax year. The census attributes **one** of them:

| variant carrying `year: i32` | raised at | in the census? |
|---|---|---|
| `Schedule1aNotOnThisYearsReturn` | `screen_inputs_tiered`, via `ri.tax_year` | **yes** — 3641/3643/3647/3660 |
| `ItemizedDeductionLimitationNotComputed` | `section_68_gate(year, …)` → `section_68_status(year)`; `return_refuse.rs:2801/2819/2828/2858` | **NO** |
| `BrokerReportingUnanswered` | `screen_broker_reporting(ri, state, year, regime)`; `return_refuse.rs:2883` | **NO** |
| `BrokerAnswerUnread` | same function | **NO** |

And the sentence `xtask blockers 2026` prints is unqualified:

> `refusals: RefuseReason has 134 variants. 5 distinct variants are raised at a site that READS the`
> `tax year (11 sites); every other variant never reads the year, so it cannot fire because the year`
> `is 2026.`

That clause is **false for `ItemizedDeductionLimitationNotComputed`**, which is the most
year-specific refusal in the file: `section_68_status(year)` is `NotApplicable` below TY2026, `Gated`
for TY2026 alone, and `ThresholdNotTranscribed` for every year after. It fires *because* the year is
2026 and for no other reason.

**Consequence, concretely.** §68 appears nowhere in the 58-row derived TY2026 blocker list — not as a
row, and not in `gates()` (7 hand-written entries; the four shut ones are the params gate, the
crypto-slice print gate, the price gate and the §111(a) worksheet gate). So the list deliberately
frozen as a PREDICTION (`3199a13de`,
`design/agent-reports/TY2026-BLOCKERS-PREDICTION-2026-09-13.txt`) omits the fact that, once January's
`FullReturnParams` land, **every itemizing TY2026 return with AGI − QBI − Schedule 1-A over $384,350
still refuses**, because the *Itemized Deductions Worksheet* lives in instructions the IRS has not
published. January's package does not clear that by arriving; it needs a transcription. The one
instrument whose job is to say what is left to do does not say it.

**Why this is the FR-114 shape and not a nit.** Two structural failures, both nameable:

1. **The B1 plant is written in the scanner's own vocabulary.** `blockers.rs:1886-1897` plants
   `if ri.tax_year > 0 { return refuse(RefuseReason::Invented, …) }` — the plant uses the needle the
   scanner already searches for. `HARNESS.md` B1's ★★ clause is that an honest kill *"cannot be
   written without discovering the blindness"*. This one could, and did.
2. **The completeness assertion is a typed list of three.** `blockers.rs:1876-1882` requires only
   `ReturnInputsYearNotStated`, `Schedule1aNotOnThisYearsReturn` and
   `StateAndLocalRefundWorksheetNotComputed`. The variant set grew by six today across five parcels
   that never saw each other; the list did not know. That is `CLAUDE.md`'s *"Derive the list, or make
   the compiler hold it"* verbatim.

Note the author already knew the *gate* half was a hand list and said so in the source
(`ty2026_rehearsal.rs:827-833`: *"blockers.rs's own gate set is a hand-written `vec![…]` of 7, which
is why it could not see `form6251_line1_rule`"*). That is an honest boundary — rule (3). The **site
census has no such boundary statement**, and it is the half that prints a universal.

Reproduce:

```

grep -n 'for needle in' crates/xtask/src/blockers.rs
```

Not filer-reachable, and no filed figure is wrong: the §68 refusal itself is correct, transcribed

`crates/btctax-oracle-harness/tests/smoke.rs:204`,

doctrine — *a single oracle disagreeing is ambiguous; two splitting is diagnostic*, and *a

* Nothing in `FOLLOWUPS.md` records it (grep for `every_admitted`, `whole corpus`, `whole-corpus`,
