## Findings

**1. [Important] `draw_edit.rs:229-268` is a FOURTH site that cannot use a `&self` accessor, and the design's remedy does not reach it.** §2.2 states "Three production sites break under a `&self` accessor" as a *measured* number. `draw_browse` (`draw_edit.rs:173`, takes `&mut EditorApp`) holds `snap` from `app.snapshot.as_ref()` (`:229`) live across `&mut app.holdings_state` (`:239`), `&mut app.disposals_state` (`:248`), `&mut app.income_state` (`:257`) and `&mut app.forms_state` (`:267`). I compiled this exact shape: two `E0502`s ("cannot borrow `app.holdings_state` as mutable because it is also borrowed as immutable … immutable borrow later used by call"). The design's prescribed fix — "move the functions into `editor.rs`, where the field is in scope" — is unavailable here: `draw_browse` is a ratatui renderer holding `&mut Frame` and building `Tabs`/`Block`/`Paragraph`; moving it into the state module inverts the separation `draw_edit` exists for. Cloning is worse than at the three `main.rs` sites (this runs every frame, not every keypress). **Fix:** specify a split accessor in `editor.rs` — e.g. `pub(crate) fn snapshot_and_table_state(&mut self, tab: Tab) -> (Option<&Snapshot>, &mut TableState)` — or a `RenderView` borrow-splitting struct, and re-state the D-5 cost as four sites, one of which needs a two-field split.

**2. [Important] §2.2's `#[cfg(test)]` accessor, placed inside `editor.rs`, silently blinds two shipped mechanized source gates.** `editor.rs` today contains **zero** `#[cfg(test)]` (verified by grep). KAT-G1's `scan_non_test` (`edit/persist.rs:2090-2104`) sets `in_test = true` on the first line starting with `#[cfg(test)]` and **never resets** — so a `#[cfg(test)] pub(crate) fn snapshot_mut(&mut self)` added inside `impl EditorApp` (`editor.rs:310+`) makes every subsequent line of `editor.rs` invisible to the `conn(` / `save(` / `apply_declare(` / `Session::create` / fs-write confinement gate, which still passes green. Independently, `production_now_utc_lines` (`main.rs:16229-16259`) sets `in_test = true` for any non-`mod`/`use` `#[cfg(test)]` and only resets on a **column-0** `}` (`:16235`), so it too goes blind from that attribute to the end of the impl block — defeating `no_direct_now_utc_in_production` (`main.rs:16192`), whose `walk` covers every `.rs` under `src/` including `editor.rs`. **Fix:** mandate that the `cfg(test)` accessors live in a separate `#[cfg(test)] impl EditorApp { … }` block placed **after all production code** in `editor.rs`, and add a KAT that both scanners still see a planted token below it.

**3. [Important] §2.5's block-title marker is width-unbuildable on Browse, so D-2's persistent marker is not delivered where the filer spends their time.** The Browse title (`draw_edit.rs:201-204`) is `format!(" btctax-tui-edit [EDITOR] — {} ", app.vault_path.display())` — a **variable-length vault path** sharing the single top border row. At 80 columns the block's interior is 78 cells; a realistic path (`/home/bcg/.local/share/btctax/vault.pgp`) yields a 68-char title, leaving **10 columns**; a macOS `~/Library/Application Support/…` path overflows the row today. ratatui 0.29 truncates a `Block` title to the available width, so an appended marker is silently clipped and D-2 ("render the stale image, MARKED") fails on the exact screen §0.1 names as the exposure ("a SHOWN readout that lags disk"). §2.5 justifies the choice on rows and clearability only and never checks width. The DefensiveFiling title (`:102`) leaves 33 columns — enough for a flag, not for §2.6's three facts. **Fix:** either take r1's other option (reserve the notice rows when `stale_after_write.is_some()` — state-conditional, shifts no unarmed golden), or specify that the marker is **prepended** and the vault path middle-elided, and state explicitly that §2.6's three facts live only in the `residue_latch_status()` refusal text.

**4. [Important] §3.5's guard predicate has a live counterexample the design itself documents 30 lines earlier.** §3.5 asserts `build_snapshot(` "appears only inside `after_write`" over non-test, comment-stripped lines of `main.rs` + `editor.rs`, and §3.4/§3.5's stated purpose is that a 28th tail "cannot silently appear". But `main.rs:4626` already spells the call `.map(btctax_tui::unlock::build_snapshot)` — **no parens** — which §0.1 explicitly notes ("which is why it appears in neither grep"). A future tail written in that idiom (or as a `let f = build_snapshot; f(session)`) passes the guard and is a stale-snapshot tail: structurally identical to how `:1347`/`:1530`/`:7032` escaped the literal-string count, which is the very failure r1-7(a) condemned. **Fix:** token on `build_snapshot` without the paren, with an explicit two-entry allowlist (`after_write` and the export re-projection), or — better — make the symbol unreachable from `main.rs` by re-exporting it privately through `editor.rs` so the compiler enforces the confinement instead of a grep.

**5. [Important] The shipped Critical has a second, structurally different chain that §3.4's mechanization cannot catch and §3 does not test.** `open_pseudo_approve_flow` (`main.rs:8185-8198`) has **no** `residue_latch_status()` check at all — I scanned every production `fn open_*`/`fn execute_*` and it is the only *flow-level* opener missing it. While `rollback_failed` is armed, `P` on Browse opens the pseudo-approve modal and its `Enter` (`:8242`) calls `persist_bulk_decisions` — a save, directly contradicting "no in-editor action will save until you quit" (`main.rs:709-710`), with **no** surviving surface required. §0.2 scopes the shipped Critical to the three uncleared surfaces; D-6 and §3.3's KAT drive only the bulk-income chain; and §3.4's "`handle_key` dispatch set ⊆ close set" guard is structurally incapable of seeing a missing opener guard, so its claim that "a 48th surface cannot silently reopen the hole" is false for this class. The shipped consumer KAT `kat_rollback_failed_latch_refuses_all_openers` (`main.rs:21381-21414`) loops only `['p','c','o','r','f','v','S','d','a']` — **9 of the 24 Browse opener keys** — which is why `P` was never caught. **Fix:** record `P` in §0.2 as a second chain of the same Critical, add a second mechanized guard (every `fn open_*_flow`/`open_*_form` body must contain `residue_latch_status()`), and extend the consumer KAT to the full `KEYMAP-SYNC` key set (`main.rs:415-483`).

**6. [Important] The three bespoke tails are enumerated but not designed: the `Err` copy decision is unstated and `main.rs:1332-1411`'s status plumbing is incompatible with `after_write`.** (a) r1-2's fix instruction "state the copy decision for the three bespoke-prefix tails" is unmet — §2.6 covers only `execute_defensive_export`'s prose. If the uniform arm text replaces them, the filer who pressed `s` (commit), `t` (park) or `a` (attest) loses the only text naming *what* landed, and §2.6 fact 1 ("the save landed and is correct") becomes contentless on the highest-stakes write in the editor. No test pins any of this: all 30 `re-projection failed` occurrences are the 27 arms plus comments at `:567`, `:4601`, `:14321`. (b) `commit_tax_inputs` does **not** set `app.status` inside the tail — it computes `let status: Option<String> = match outcome {…}` and assigns unconditionally at `main.rs:1411`. An `after_write` that sets `self.status` internally is then overwritten by `app.status = status` (with `None` if the arm yields `None`), so the filer commits a full return and sees **no** confirmation. §2.3's "All 27 sites call this and nothing else … one convention, not two" does not hold for this site without restructuring `:1332-1411`. **Fix:** add a third axis to the site taxonomy (literal / snapshot-derived / status-hoisted-to-an-outer-binding), name `:1347` as the one hoisted site with its restructuring, and state per-tail whether the bespoke prefix survives into the arm text.

**7. [Minor] §2.2's "moving the three functions" is inaccurate for two of the three.** `main.rs:4116-4124` is a `KeyCode::Char('t')` **match arm** inside `handle_declare_flow_key`, and `:4320-4327` is the `KeyCode::Enter` arm inside `handle_promote_flow_provenance_key`; only `promote_flow_review` (`:4367-4376`) is a standalone fn.
