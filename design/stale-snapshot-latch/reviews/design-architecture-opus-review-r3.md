## Findings

**1. [Critical] §2.4.1's "flush first" obligation makes `close_all_mutation_surfaces` save the unrevertable residue to disk — the exact thing the caller's own copy promises cannot happen.**
`close_all_mutation_surfaces`' only shipped caller is `on_persist_error`'s `ResidueLive` arm (`main.rs:705-713`), which fires when a save failed **and** `session.restore(pre)` also failed (`edit/persist.rs:219-222`), i.e. unrevertable appends are live in the in-memory DB. The status it sets one line earlier reads *"the vault on disk is unchanged; no in-editor action will save until you quit"* (`main.rs:708-711`). §2.4.1 now mandates that `close_all` **flush first**. That flush is `flush_tax_inputs_draft` (`main.rs:960`) → `edit::persist::form_save_draft` (`edit/persist.rs:101-107`) → `input_form_store::save_draft`, whose body is `set_draft_row(…)?; sess.save()?;` (`crates/btctax-cli/src/input_form_store.rs:126-131`) → `Session::save` → `self.vault.save()` (`crates/btctax-cli/src/session.rs:467-470`), which writes the **entire** in-memory DB image (the same image `snapshot()`/`restore()` round-trip, `session.rs:473-482`). **Failure scenario:** a bulk-void `save_or_rollback` fails, the rollback fails, `on_persist_error` arms `rollback_failed`, `close_all` flushes a dirty tax-inputs draft — and the residue the filer was told could not be reverted is now permanently in the vault, under a status telling them the vault is unchanged. Second, smaller defect on the same path: `flush_tax_inputs_draft`'s error arm does `app.status = Some(format!("{e}"))` (`main.rs:982`), overwriting the CRITICAL notice that `draw_defensive_filing` red-styles on `starts_with("CRITICAL")` (`draw_edit.rs:155`). **Fix:** the flush must be caller-conditional — `close_all_mutation_surfaces(&mut self, may_save: bool)` (or two entry points). The `ResidueLive` path must **not** flush (any `save()` is forbidden by the latch's definition); there, either keep `tax_inputs_form` open or null it with copy that names the lost year. Only `apply_reprojection`'s stale path (where memory == disk, because the persist succeeded) may flush, and it must not let the flush's error clobber the arm status. *(No recursion hazard: `form_save_draft` returns `CliError`, routed straight to `app.status`, never to `on_persist_error` — that part is sound.)*

**2. [Critical] D-7's exemption is unreachable from 25 of the 27 arming tails, so §2.6's "primary mitigation" for the tax-r1 I-3 lockout does not exist.**
`execute_defensive_export` has exactly one production call site: `main.rs:512`, inside the `EditorScreen::DefensiveFiling` arm **and** inside `if let Some(dash) = app.defensive_dashboard.as_mut()` (`:501`). `EditorScreen::DefensiveFiling` is assigned in production at exactly one place — `editor.rs:514`, at the end of `open_defensive_filing`, whose first statement is the latch gate at `editor.rs:474`. §2.4 step 3 routes "the ~27 opener sites" to `stale_or_residue_latch_status()` and exempts only `execute_defensive_export`; `open_defensive_filing` is one of those 27 (it is the 27th, the sole non-`main.rs` caller). So while `stale_after_write` is armed, Browse `w` (`main.rs:478`) refuses, the screen is unreachable, and `x` is unreachable. Only the two tails that arm *while already on that screen* — `declare_flow_confirm` (`:4217`) and `promote_flow_confirm` (`:4498`) — leave `x` usable, and only because `close_all_mutation_surfaces` (`:719-764`) does not null `defensive_dashboard`. **Failure scenario:** the filer voids a decision on Browse, the re-projection fails, the latch arms, `w` refuses, they quit as instructed, and `open_session`'s own `build_snapshot` (`crates/btctax-tui/src/unlock.rs:129`) fails deterministically — the exact tax-r1 I-3 lockout, with §2.6 asserting a mitigation that was never reachable. **Fix:** `open_defensive_filing` (`editor.rs:474`) must **keep** `residue_latch_status()`, not the combined one — the dashboard is read-only (C-3) and both write flows are separately gated at `open_declare_flow` (`main.rs:3997`) and `open_promote_flow` (`:4253`), which take the combined latch. Restate D-7 as exempting the *export route* (`w` → dashboard → `x`), and add a KAT that `w` still opens the dashboard while the stale latch is armed.

**Enumeration of all 27 `residue_latch_status()` call sites and which each should call** (26 in `main.rs`, 1 in `editor.rs`): **`residue_latch_status()` (original, 2 sites):** `execute_defensive_export` `main.rs:4616` (D-7, as designed) and `EditorApp::open_defensive_filing` `editor.rs:474` (**the design gets this one wrong** — finding 2). **`stale_or_residue_latch_status()` (combined, 25 sites):** `open_profile_form` `:775`, `open_tax_inputs_form` `:838`, `open_method_election_flow` `:2698`, `open_classify_inbound_flow` `:3321`, `open_reclassify_outflow_flow` `:3418`, `open_reclassify_income_flow` `:3605`, `open_set_fmv_flow` `:3712`, `open_void_flow` `:3939`, `open_declare_flow` `:3997`, `open_promote_flow` `:4253`, `open_select_lots_flow` `:5466`, `open_set_donation_details_flow` `:5664`, `open_link_transfer_flow` `:5818`, `open_classify_raw_flow` `:6224`, `open_safe_harbor_attest_flow` `:6811`, `open_safe_harbor_allocate_flow` `:7109`, `open_bulk_link_transfer_flow` `:7392`, `open_bulk_self_transfer_in_flow` `:7843`, `open_bulk_classify_income_flow` `:8348`, `open_bulk_resolve_conflict_flow` `:8771`, `open_bulk_void_flow` `:9027`, `open_bulk_reclassify_outflow_flow` `:9252`, `open_match_self_transfers_flow` `:9589`, `open_resolve_conflict_flow` `:9834`, `open_optimize_accept_flow` `:10107`. **3. [Important] §2.5 still does not deliver D-2's marker on Browse, and on the one screen it does amend it reserves an EMPTY band.**
Two independent gaps. (a) **Browse has no notice rows to reserve.** Its layout is built at `draw_edit.rs:183-195` from `[Length(3) tab bar, (optional) Length(1) pseudo banner, Min(0) content, Length(1) footer]`; the only status surface is the single footer row at `:280-294`, which renders `app.status` *or* the keybinding hint. The notice-row machinery §2.5 amends (`:107-119` reservation, `:152-163` render) exists **only** in `draw_defensive_filing`. §2.5 cites `main.rs:414` (Browse's status clear) but never says what changes in the Browse renderer, while §3.12 promises "Browse at 80 columns with a long vault path" goldens for a marker that has no mechanism. (b) **Reserving is not rendering.** The render guard is `if let (Some(rect), Some(s)) = (notice_area, status)` (`draw_edit.rs:152`); `main.rs:494` clears `app.status` on every keypress on that screen. Reserving the rows on `stale_after_write.is_some()` while `status` is `None` therefore draws a blank 3-row band. This is the third consecutive round in which D-2's persistent marker is specified but not deliverable. **Fix:** state (i) the fixed marker text rendered into the notice rect whenever armed, independent of `app.status`, and (ii) a Browse mechanism — a state-conditional `Constraint::Length(1)` row pushed into the `:183-188` constraints vec with the `content_idx`/`footer_idx` bookkeeping at `:194-195` extended, exactly mirroring the PSEUDO banner at `:184`/`:213-224` that §2.5 already cites as the precedent.

**4. [Important] `snapshot_and_table_state(&mut self, tab) -> (Option<&Snapshot>, &mut TableState)` solves `draw_browse` only under two rules the design never states, and its return type is not total over `Tab`.**
I modelled `EditorApp`/`draw_browse` in a scratch crate and compiled five variants. Results: today's field-access shape compiles (disjoint fields through `&mut app`); the naive `&self` accessor is `E0502` (confirming arch-r2-1); **the split accessor called once, with the rest of `draw_browse` unchanged, is `E0503`** — `cannot use app.holdings_sort because it was mutably borrowed`, because the returned tuple keeps `*app` mutably borrowed and `draw_edit.rs:237-238`, `:246-247`, `:255-256` read `app.{holdings,disposals,income}_{sort,cursor}` *inside* the render call; **calling it twice with the first `&Snapshot` still live is `E0499`** (`cannot borrow *app as mutable more than once`). It compiles only if (i) every other `app.*` read in `:229-268` — `selected_year`, `tab`, all three sort/cursor pairs — is hoisted above the call, and (ii) it is called exactly once per frame (or once per match arm, with `snap` re-taken each time). Separately, `Tab::Tax` (`:259-261`) and `Tab::Compliance` (`:269-271`) pass **no** `TableState`, so a `-> &mut TableState` return has no honest value for them. **Fix:** either state rules (i)+(ii) and change the return to `(Option<&Snapshot>, Option<&mut TableState>)`, or adopt the `RenderView`/borrow-splitting struct arch-r2 offered as the alternative — one call returning `Option<&Snapshot>` plus all four `&mut TableState`s plus the Copy sort/cursor values, which removes both rules.

**5. [Important] §2.2's ★ "each migrated helper calls `live_snapshot()` and refuses" does not compile — it reintroduces the very `E0502` that made those three sites accessor-breakers.**
`live_snapshot(&self) -> Result<&Snapshot, StaleReason>` borrows all of `self`. All three migrated bodies then need `self.{declare,promote}_flow.as_mut()` (`main.rs:4120`, `:4325`, `:4373`). I compiled the prescribed shape: `error[E0502]: cannot borrow self.promote_flow as mutable because it is also borrowed as immutable`. The working shape is a boolean latch probe whose borrow *ends*, then the raw field — which compiles, but means these three sites read `self.snapshot` **directly**, so D-5 ("construction, not convention") does **not** hold at exactly the three sites that build the `Acknowledgment.shown_terms` §6664(c) record and the promote plan. That is tax-r1 C-1's objection, re-formed. **Fix:** specify the probe form (`fn stale_reason(&self) -> Option<StaleReason>` or `stale_or_residue_latch_status()` returning an owned `String`, checked and dropped before the field borrow), and state plainly that at these three sites the guarantee is held by the §3.3 KATs, not by the compiler — so those KATs are gating, not illustrative.

**6. [Important] §3.5(b)'s guard pattern excludes the site chain A's own fix lives at, and excludes `open_defensive_filing`.**
The guard is specified as "every `fn open_*_flow` / `open_*_form` body contains a latch check". I enumerated all production `fn open_*`: 24 `_flow`, 2 `_form` (`main.rs:774`, `:837`), **11 `_modal`** (`main.rs:1264, 1565, 7210, 7712, 8087, 8601, 8899, 9124, 9467, 9667, 10182`), and `EditorApp::open_defensive_filing` (`editor.rs:469`) — 38 total. §2.4 step 2's chain-A fix goes at `main.rs:8640`, inside **`open_bulk_income_modal`** (`:8601`) — a `_modal`, invisible to the pattern. **7. [Important] §3.6's *preferred* remedy is unachievable, and the only way to force it breaks §5's SemVer claim.**
"re-export `build_snapshot` privately through `editor.rs` so `main.rs` cannot name it" cannot work: `build_snapshot` is `pub fn` at `crates/btctax-tui/src/unlock.rs:171`, inside `pub mod unlock` (`crates/btctax-tui/src/lib.rs:45`), in a **separate library crate** that `btctax-tui-edit` depends on.
