## VERDICT

`NOT GREEN (1C/6I)` — the design's central simplification (§2.4) is factually false against
`close_all_mutation_surfaces`, its write-tail class is under-counted by three members, and its one-size
`after_write` signature cannot express 13 of the 24 tails it claims to absorb.

---

**1. [Critical] §2.4's "every modal and flow is `None` while armed" is false: `close_all_mutation_surfaces` does not clear three of the surfaces `handle_key` dispatches on, and the design explicitly waives the refusal audit on that basis.**
`handle_key` (`main.rs:126-386`) dispatches on 47 `Option` fields plus `help_open`; `close_all_mutation_surfaces` (`main.rs:719-764`) clears 44. Diffing the two lists element by element, the uncleared dispatch targets are **`tax_inputs_form` (`main.rs:377`), `bulk_income_flow` (`main.rs:327`), `bulk_income_modal` (`main.rs:241`)** (plus `help_open`, which D-2 intends to stay live). The reachable failure: the tax-inputs PARK tail (`main.rs:1528-1550`) deliberately leaves the form open (`main.rs:1533-1537` sets `form.parked = true`), so a park whose re-projection fails arms the latch, runs `close_all_mutation_surfaces()`, and the form survives — `handle_key` then claims every key at `:377` and never reaches the screen-level handler, so D-1 ("every action that derives a number or a decision REFUSES") is unmet on a live write surface. This is also a pre-existing hole in the shipped `rollback_failed` latch, since `on_persist_error`'s `ResidueLive` arm (`main.rs:712`) calls the same fn. **Fix:** add the three fields to `close_all_mutation_surfaces`, and replace §2.4's prose claim with a mechanized guard (a test asserting the `handle_key` dispatch set ⊆ the `close_all` clear set) so a 48th surface cannot silently reopen the hole.

**2. [Important] The write-tail class has 27 production members, not 24 — the literal count is a count of one copy string, not of the defect.**
`grep -n 'app.snapshot = Some(snap)'` over lines 1-10706 returns **28** sites, and `build_snapshot(` returns **27**. Three of them carry the identical Ok/Err shape with *bespoke* Err copy and therefore never appear in the `"Saved but re-projection failed"` grep: `main.rs:1345-1358` (tax-inputs commit — `"committed {year} as {label}, but re-projection failed…"`), `main.rs:1528-1550` (tax-inputs park), and `main.rs:7031-7046` (safe-harbor attest — `"Attested but re-projection failed…"`). Each leaves `app.snapshot` on the pre-write image exactly as the 24 do; the attest one is the highest-stakes write in the editor (it is the site the `attest_save_failed` latch exists for). D-3's "editor-wide invariant, fix the class not the instance" is therefore not established by the design as scoped, and the design's own §0 assertion that "**The number is 24**" is wrong for the class it names. **Fix:** re-derive the class from `build_snapshot(` (27 production sites, less the deliberate one at `:4622`), enumerate all of them in §0, and state the copy decision for the three bespoke-prefix tails.

**3. [Important] `after_write(&mut self, success: impl Into<String>)` cannot serve 13 of the tails: their success status is derived from the snapshot that does not exist until the rebuild succeeds.**
The Ok arms at `main.rs:2665` (`derive_set_fmv_status(&snap, …)`), `:3201` (`derive_void_status(&snap, …)`), `:7036` (`derive_attest_status`), `:7307` (`derive_allocate_status`), `:7791` (`derive_bulk_link_status`), `:8157` (`derive_bulk_sti_status`), `:8257` (`snap.state.pseudo_synthetic_count`), `:8683` (`derive_bulk_income_status`), `:8972` (`derive_bulk_resolve_status`), `:9547`, `:9751`, `:10036`, `:10379` all compute the status string *from the freshly rebuilt `snap`*. A caller-supplied `impl Into<String>` cannot express any of them, so §2.3's "THE write tail. All 24 sites call this and nothing else" is unbuildable as written. Worse, §3.3's three chosen end-to-end KATs ("a defensive declare, one bulk path, the profile save") pick from the 11 sites whose status *is* a plain literal (`main.rs:563`, `:4222`), so the hard case would not be covered. **Fix:** change the parameter to `impl FnOnce(&Snapshot) -> String` (or take both a static message and an optional deriver), and pick at least one snapshot-derived site for the representative KATs.

**4. [Important] Routing reads through a `&self` accessor breaks three call sites the borrow checker accepts today only because they are disjoint *field* borrows — and the repo has already written this lesson down for `session`.**
`main.rs:4116-4124`, `:4320-4327`, and `:4368-4375` (`promote_flow_review`) all hold `app.snapshot.as_ref()` live *inside* an `if let Some(flow) = app.declare_flow.as_mut()` / `app.promote_flow.as_mut()` body (e.g. `:4374` `flow.review(&snap.events, &snap.prices, &cfg, now)`). I confirmed with `rustc 1.97.0-nightly` that the field form compiles and the accessor form is `error[E0502]`. The usual escape hatch — `let EditorApp { snapshot, promote_flow, .. } = app;` — is unavailable once the field is private to `editor`, so these three must either clone `snap.events`/`prices`/`tables` per keypress (the whole ledger, on `t`/`Enter`/`Tab`) or migrate into `editor.rs` — i.e. the "methods that move" list in §2 is incomplete. Note `main.rs:833-834` already documents the identical decision for the sibling field: *"`session` is a bare field; `app.session` and `app.tax_inputs_form` are borrowed as DISJOINT fields (**no `session()` method**)"*. The design proposes for `snapshot` precisely the pattern the tree rejected for `session`, and never engages that comment. (Good news, quantified: the *other* 22 production sites are safe — NLL handles the let-else-with-mutation-in-`else` form at `:4643-4650` and the early-return form at `:5886`/`:7401`; I verified both compile.) **Fix:** name the three sites, decide clone-vs-migrate for each, and reconcile with `main.rs:833-834`.

**5. [Important] The test blast radius is ~111 sites in sibling `#[cfg(test)]` modules; §3.5 accounts for one, and the helper it proposes is not implementable because `Snapshot` is not `Clone`.**
`mod tests` is declared at `main.rs:10706-10707` — a child of the crate root and therefore a *sibling* of `editor`, so it loses access identically to `draw_edit`/`defensive_dashboard`. Of the 168 `app.snapshot` sites in `main.rs`, **106 are at lines > 10706**, including 12 assignments (`:12858, :12910, :12992, :13115, :13274, :13445, :13613, :13839, :14013, :14303, :14395, :17039`) and 3 `as_mut` sites the design never mentions (`:13324`, `:13376`, `:14471`), plus `defensive_dashboard.rs:1119/1148/1172/1188` and `draw_edit.rs:6999` (both files' `#[cfg(test)]` starts at `:459` and `:5944`). A read-only accessor serves none of the assignments. And `btctax_tui::app::Snapshot` (`crates/btctax-tui/src/app.rs:104`) carries **no derives at all** and has no manual `Clone` impl, so §3.5's "`#[cfg(test)]` helper … that **installs** a stale snapshot" cannot be fed: the KAT at `main.rs:14343-14344` works by emptying two fields of the *fixture's own* snapshot in place. **Fix:** specify a `#[cfg(test)] pub(crate) fn snapshot_mut(&mut self) -> Option<&mut Snapshot>` (plus a setter) in `editor.rs` and state the ~111-site mechanical migration explicitly. This does *not* re-open D-5's convention hole — `cfg(test)` keeps production construction-enforced — but the design must say it exists.

**6. [Important] D-2's persistent STALE marker is asserted but not constructed: §2.5 forecloses a new row, and there is no existing real estate that survives `status == None`.**
On `DefensiveFiling`, the NOTICE rows are allocated **only when a status is present** — `draw_edit.rs:108-119`: `let status = app.status.as_deref(); match status { Some(_) => …split…, None => (inner, None) }`, and `:152` renders only `if let (Some(rect), Some(s))`. So a latch-derived marker with `status == None` (exactly the state §2.5 says it must survive into) gets zero rows. On Browse the footer is a single line that is status **XOR** keybindings (`draw_edit.rs:280-292`), and its own in-source comment (`:284-288`) records that the keybinding string *already* overflows 80/120 columns. Consequently, while armed the filer sees either the arm/refusal text (with its three §2.6 mandatory facts) or the marker — never both — and after any keypress clears the status, neither. **Fix:** either reserve the notice rows when `stale_after_write.is_some()` (a state-conditional reservation, which does not shift any golden in the unarmed state) or put the marker in the block title (`draw_edit.rs:102`, `:201-204`) — and say which.

**7. [Important] §3.3's structural guard does not do what §3.3 claims, and would be red on first run.**
(a) "Assert the literal … occurs ZERO times in `main.rs`" cannot "catch a 25th tail added later" — a new tail with bespoke copy passes it, which is precisely how `:1352`, `:1547` and `:7043` escaped both the FOLLOWUP's count and this design's. The guard's entire soundness therefore rests on the `build_snapshot(` half. (b) That half is unscoped: `build_snapshot(` appears at **18 test-region sites** in `main.rs` (`:13443, :13611, :13837, :14011, :15741, :15863, :16105, :17038, :17687, :17922, :18021, :18200, :18687, :18804, :19168, :20306, :21294, :25345`) and in a doc comment at `editor.rs:96`. (c) After the move, `after_write` lives in `editor.rs`, so the guard must span two files. The `edit/persist.rs:2016-2070` precedent does exactly this correctly (separate `non-test` / `test_region` token lists plus comment stripping at `:2072-2075`) — the design should cite that shape rather than describe an unscoped whole-file grep. **Fix:** scope the guard to non-test, comment-stripped lines across `main.rs` + `editor.rs`, and drop the claim that the literal check catches new tails.

**8. [Minor] §2.4's refusal enumeration omits two live Browse openers, and the design never proposes the chokepoint that already exists.**
Browse dispatches 24 opener keys (`main.rs:445-478`); §2.4's prose list omits `T` → `open_tax_inputs_form` (`:447`/`:837`) and `P` → `open_pseudo_approve_flow` (`:473`/`:8185`) — and `open_pseudo_approve_flow` does not check `residue_latch_status()` at all today (27 production callers; it is absent between `:8348` and the pseudo opener). D-1 says the latch "mirrors the shipped `rollback_failed`/`residue_latch_status` pair", yet §2.4 invents a fresh refusal surface instead of extending `residue_latch_status()` (`main.rs:672-690`), which would deliver ~27 opener refusals for free and is already KAT'd (`main.rs:21361-21371`). Say why not, or use it.

**9. [Minor] Armed-plus-fresh-snapshot is reachable through the export path, and the design does not specify the ordering that prevents it.**
`execute_defensive_export` re-projects and *assigns* `app.snapshot` at `main.rs:4622-4631`, after the `residue_latch_status()` gate at `:4616`. If the new `x` refusal is placed anywhere after `:4622`, a successful rebuild leaves `snapshot` current while `stale_after_write` stays armed forever (D-4: zero clear sites) — the marker then lies and every deriving key refuses a perfectly current editor. That is verbatim the failure mode the shipped rationale at `main.rs:4606-4610` argues the latch would introduce ("a stuck flag refusing a perfectly valid export"); the design neither cites that comment nor says what becomes of it. State that the refusal must precede `:4622`, and amend or delete `:4602-4610`.

**10. [Nit] Visibility of the moved methods is unspecified, and the dependency runs both ways.**
Private items in `editor.rs` are invisible to the crate root, so `after_write` must be at least `pub(super)` for `main.rs`'s tails to call it. Conversely `residue_latch_status` stays at `main.rs:672` and is already called from `editor.rs:474` — §2's "the `main.rs:668` impl block loses field access" is right, but the block is not self-contained in the other direction either. Also, `on_persist_error` (`:697`) and `close_all_mutation_surfaces` (`:719`) touch no snapshot field, so §2's claim that they must move is unmotivated.

**11. [Nit] §2.2's editor-internal count is off by one.** `editor.rs` has four snapshot references (`:320` literal, `:407`, `:478`, `:530`), not three.

## Verified sound

- **The 24-literal enumeration.** All 24 cited line numbers are exact, and `:4601`/`:14321` are genuinely doc comments; the FOLLOWUP's "26" did count its own documentation. No test asserts the literal (all 26 hits are ≤ `:10392` plus the `:14321` doc).
- **Module topology and D-5's premise.** `mod editor;` is declared at `main.rs:14`, so `editor` is a child of the binary crate root; `pub(crate)` genuinely cannot deliver D-5, and privatizing to `editor` does cost the `main.rs:668` impl block field access.
- **The `is_some()` dashboard guard in §2.3 is load-bearing and correct.** `refresh_defensive_dashboard` (`main.rs:4562-4579`) does create `DefensiveDashboardState` unconditionally after its no-snapshot early return, and `defensive_dashboard` *is* nulled on Esc (`main.rs:498`), so the guard cannot be defeated by a stale dashboard left over from an earlier visit.
- **The `session`-iff-`snapshot` invariant.** `editor.rs:93` holds: the only two setters (`:400-411`, `:524-534`) set both, and nothing ever sets either back to `None`. §2.3's `None` arm really is production-unreachable.
- **D-4's "zero clear sites" survives the unlock paths.** The only production `screen = EditorScreen::Unlock` is `main.rs:406` (Locked → `r`), and `Locked` is only reachable pre-unlock, so `do_unlock`/`try_env_passphrase` cannot re-assign `snapshot` while armed.
- **§2.5's premise about the status.** `main.rs:494` does run `app.status = None;` before the `DefensiveFiling` dispatch, so a status-derived marker really would be destroyed by the next keypress.
- **`edit/*.rs` is out of scope.** No file under `crates/btctax-tui-edit/src/edit/` accesses the `snapshot` *field* at all; `persist.rs`'s "snapshot" mentions are `session.snapshot()` DB-rollback machinery, exactly as §2.2 says.
- **The borrow cost is bounded.** Only 3 of 25 production `as_ref` sites break; the let-else-with-`else`-mutation and mid-function early-return forms are NLL-safe (verified by compiling both shapes).
- **SemVer PATCH.** `crates/btctax-tui-edit/Cargo.toml:13-15` declares a `[[bin]]` target and no lib, so there is no published API surface to break.
